# ADR-003: Separate Release Assessment from Test Execution

## Status

Accepted

## Context

The framework runs multiple types of validation:

- Python tests
- Playwright tests
- API health checks
- Metrics checks
- Synthetic canaries
- Security workflow validation
- Performance trend analysis

Test execution answers whether individual checks passed or failed.

Release assessment answers a broader question:

```text
Is the system ready to release based on the available evidence?

These are related but separate responsibilities.

Combining test execution and release recommendation into the same logic would make the framework harder to maintain and harder to explain.

Decision

Separate release assessment from individual test execution.

Tests and validation checks should produce evidence.

The release assessment layer should evaluate that evidence and produce a release recommendation.

The release assessment may consider:

Total checks
Failed checks
Risk level
Health status
Observability status
Performance signals
Security validation signals
Alternatives Considered
Let each test decide release readiness

Each test could determine whether a release should proceed.

This was rejected because individual tests usually lack the full context needed for release decisions.

Use only CI pass/fail status

The project could rely only on whether the full CI job passed.

This was rejected because CI pass/fail status does not explain risk level or provide a structured release recommendation.

Combine all validation and assessment in one script

A single script could run checks and decide release status.

This was rejected because it would tightly couple execution and decision-making, making future changes harder.

Consequences
Positive Consequences
Tests remain focused on validation
The release engine remains focused on decision-making
Evidence can be collected from multiple sources
Release recommendations become easier to explain
The framework better reflects real-world quality engineering workflows
Tradeoffs
More structure is required
Evidence must be passed from validation layers to the assessment layer
Documentation is needed to explain the separation of responsibilities
Outcome

Separating release assessment from test execution makes the framework more maintainable and more realistic.

It supports the project’s goal of demonstrating evidence-driven release readiness rather than simple pass/fail automation.
